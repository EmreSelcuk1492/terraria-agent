## Python modules (`agent/terraria_agent/`)

| Module | Entry point | Summary |
|---|---|---|
| `__init__` |  | Claude plays Terraria through the Terraria Agent Bridge tModLoader mod. |
| `__main__` | `python -m terraria_agent` |  |
| `agent` |  | The agent loop: observe -> the model picks a skill -> the bridge runs it in game -> result goes back. |
| `backends` |  | Model backends. Each one keeps its own message history in its provider's format. |
| `bridge` |  | HTTP client for the tModLoader bridge mod (or mock_bridge.py). |
| `clips` | `python -m terraria_agent.clips` | Put screen recordings of a run on lab.emrecanselcuk.com, next to the results they show. |
| `director` | `python -m terraria_agent.director` | The Director: plays the first in-game days of a fresh world on its own. |
| `lab` | `python -m terraria_agent.lab` | Publish runs to lab.emrecanselcuk.com (Supabase lab_* tables), so the public page updates itself. |
| `llm_bench` | `python -m terraria_agent.llm_bench` | LLM track: a local open model plans programs of bridge skills, the game verifies them, a library keeps what works. |
| `memory` |  | Lessons that survive between runs. Loaded into the system prompt at start, appended via the `remember` tool. |
| `prompts` |  |  |
| `repl` |  | Drive the bridge by hand, no model. The free way to test skills in game. |
| `scenarios` | `python -m terraria_agent.scenarios` | Scenario tests: short, repeatable situations against a real game (or the mock), scored pass/fail. |
| `showcase` | `python -m terraria_agent.showcase` | A narrated tour of what the agent can do, for watching (or recording) on a real screen. |
| `skill_library` |  | Skill library: programs the planner wrote that passed a check in the real game, kept for reuse. |
| `telemetry` |  | PostHog AI observability: every model call, skill call and run shows up in PostHog's LLM analytics. |
| `tools` |  | Tool definitions Claude sees, and how each call is carried out against the bridge. |

## Tests (`agent/tests/`, offline, mock world)

- `test_director.py` (17 tests): The director against the mock world: the whole starter plan, night rules, and the no-progress guard.
- `test_lab.py` (4 tests): The lab is public: what leaves for it is scrubbed, and tests can't reach it at all.
- `test_llm_bench.py` (8 tests): The LLM track's loop against the mock world, with a scripted planner standing in for the model.
- `test_loop.py` (13 tests): Offline tests: the agent loop + tools against mock_bridge, with a scripted stand-in for the Claude API.
