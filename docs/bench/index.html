A local model that writes its own skills

For each task, gpt-oss:20b (running on the Mac, no cloud) writes a program of game skills. The game runs it and checks the goal against the inventory; failures go back to the model with the error, up to 3 tries. Programs that pass are saved to a skill library and offered for later tasks. Macros like "obtain" are switched off here, so the model has to compose the crafting chains itself. Pass 1 starts with an empty library; pass 2 starts on an identical world with what pass 1 learned.

What is and isn't measured

Real game, real inputsMovement, fighting and item use go through the player's controls each tick, the way a keyboard would. The navigator from TerraBlind (Reisenbug, MIT) runs with its free-item helpers switched off.
Our shortcutsMining waits a simulated swing time, then breaks the tile directly; the dig-in bunker places its roof blocks instantly from the inventory. Both are next to move to real item use.
Test setup, not skillsScenarios teleport, spawn enemies and reset the character to set a known start. The agent never calls these.
Small numbersSuites run each scenario 1 to 3 times, so one attempt moves a pass rate a lot. More repeats come next; every report is in the repo.
